# Territorial offices

Source-extracted monthly territorial observations (`_OFFICES-REG.csv`).

`YYYY-MM-01_OFFICES-REG.csv` is a converted representation of the Bank of Russia's [monthly territorial-presence XLSX releases](https://www.cbr.ru/statistics/bank_sector/lic/) (`DivisionsPerRegion_DDMMYY.xlsx`). The filename identifies the **official first-of-month reference date**, not download or publication time. These publications describe geographical aggregates rather than individual bank observations. They may include categories absent from `OFFICES`, such as mobile offices or historical cash-service mobile points and representative offices. Preserve each release's literal source headings and values; a published change of classifications does not retroactively amend earlier releases.

The two traceability columns are `source_row` (physical row number in the source XLSX worksheet) and `section_label` (the published federal-district heading applying to the following region records). The source workbook contains one populated worksheet, so its redundant sheet name is not repeated in every CSV row. District subtotal rows provide section labels rather than standalone observations; the national total remains in the CSV, and the four trailing ungrouped territories retain an empty `section_label`. The final district boundary is checked against the publisher's subtotal rather than assigned from a hardcoded territory list. Published numeric values and literal indicator headings are preserved without inferred zeros or retrospective harmonization. When the source XLSX contains formulas, CSV cells retain the XLSX **cached values**, never recalculated results; the original formula text, attributes, physical row and source-column identifiers are recorded in the publication commit's `formula_cells` provenance instead of an extra CSV column. Missing formula caches stop conversion. The XLSX source URL and SHA-256 are also preserved in the publication commit, while the original XLSX is not retained in the corpus. Excel's overall title, numbered header guide (including nonconsecutive ordinal codes such as 1,2,3,4,5,9), and trailing notes are omitted; column headings, country total and territorial data are retained. District subtotal figures, formatting, merged-cell layout and source footnotes are not recreated in the CSV; consult the primary XLSX where those details matter.

The separate [regional collector](../../../../scripts/capture_cbr_offices_reg.py) and [monthly discovery workflow](../../../../.github/workflows/capture-cbr-offices-reg.yml) check the official index daily at 02:17 UTC (05:17 UTC+03), retrieving missing releases newer than the latest archived monthly date. A missing new official release creates no file; a new release creates one CSV, never a synthetic daily snapshot. The workflow's manual `backfill` mode retrieves missing historical reference dates, `verify` checks existing CSVs, and `dry_run` suppresses publication. An existing file is never silently overwritten.

**Do not combine, add or compare territorial rows as if they were disjoint.** The monthly tables can contain country, district, region and nested territorial totals (for example autonomous okrugs within regions). Absence of an indicator column is not zero. Any harmonization of categories, dates, boundaries or territorial nesting is a separate, documented analytical bridge and not part of this evidence layer.

Treat identifier and textual source columns as text when importing CSV into spreadsheet software. This CSV is not an official source CSV or a full preserved source publication. Source strings beginning with spreadsheet formula characters are preserved and are not made safe for direct spreadsheet opening.

The [bank-level daily series](../bank-regional-offices/) is independent. No common bank-level time series is implied.
