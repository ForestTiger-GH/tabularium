# Credit institution structural units

This directory holds two distinct, dated **wide CSV representations** of Bank of Russia publications, organized as `YYYY/YYYY-MM-DD_SUFFIX.csv`. They coexist but are not directly interchangeable: the source observations, territorial coverage and date semantics differ.

## Bank-by-region observations (`_OFFICES.csv`)

`YYYY-MM-DD_OFFICES.csv` is an extraction of the Bank of Russia's [bank-by-region HTML table](https://www.cbr.ru/banking_sector/credit/cstat/). The filename identifies the fixed UTC+03 retrieval date of automated captures; retrospectively uploaded historical CSVs retain the date labels supplied with their historical files, which do not independently establish the true retrieval date. Every published bank-by-region data row appears once.

The first two columns, `source_row` and `section_label`, are traceability fields: `source_row` is the physical source row (HTML for automatic captures, XLSX worksheet for earlier converted snapshots); `section_label` is the preceding territorial section label. Some older publications have an empty label rather than the later literal `-`, and neither may be silently substituted for the other. Subsequent columns retain the source's actual published headers and ordering. Early forms include office categories absent in later forms; names and values are not retroactively harmonized.

The extraction decodes HTML entities and folds layout whitespace, but does not calculate or infer values; blank, `0` and `—` remain distinct. Rows are observed on the extraction date, not necessarily the source's statistical reference date. Context outside the HTML table is not archived. The [collector](../../../../../scripts/capture_cbr_offices.py) and [daily workflow](../../../../../.github/workflows/capture-cbr-offices.yml) capture at 01:17 UTC (04:17 UTC+03). The [read-only monitor](../../../../../.github/workflows/check-cbr-offices.yml) checks the day's file at 09:17 UTC.

## Monthly territorial observations (`_OFFICES-REG.csv`)

`YYYY-MM-01_OFFICES-REG.csv` is a converted representation of the Bank of Russia's [monthly territorial-presence XLSX releases](https://www.cbr.ru/statistics/bank_sector/lic/) (`DivisionsPerRegion_DDMMYY.xlsx`). The filename identifies the **official first-of-month reference date**, not download or publication time. These publications describe geographical aggregates rather than individual bank observations. They may include categories absent from `OFFICES`, such as mobile offices or historical cash-service mobile points and representative offices. Preserve each release's literal source headings and values; a published change of classifications does not retroactively amend earlier releases.

The `source_sheet` and `source_row` columns identify the original worksheet and physical XLSX row. The third technical column, `source_formulas`, contains optional JSON mapping one-based XLSX column indices to original formulas and attributes; an empty field means none. The fourth technical column, `section_label`, carries the published federal-district heading for constituent territorial rows without any hardcoded list of district names. Published district subtotals become structural section labels rather than standalone CSV observations: their literal headings populate `section_label` on following regional records, but their numeric totals are not repeated. The published country total remains a separate observation with an empty `section_label`. For ungrouped territories following the last district, the converter determines the district boundary by reconciling its published subtotal with the succeeding source rows, leaving later rows ungrouped; ambiguous cases stop conversion. For formula cells, the indicator column contains the **cached value stored in the publisher's XLSX**, not a recomputation, and a missing cached value blocks conversion. Remaining columns preserve original published cell values in source-column order; where the XLSX has multiple levels of column headers, readable header paths concatenate published header strings using ` / `. A completely unlabeled source column is identified as `source_column_N` (original one-based column index), never assigned an inferred indicator name. CSV extraction retains the published column names, national total and regional and nested-territory records; it does not reproduce the district-total rows, which serve only as section headings. Those original district totals remain retrievable from the cited XLSX source. The publication title above the table, Excel's numeric column-numbering guide, and footnotes or explanatory rows beneath the table are excluded. Extraction folds whitespace and does not recreate merged-cell layout, workbook formatting or the original XLSX itself. It may reject ambiguous or unexpected workbook layouts rather than publish a speculative representation. Source XLSX bytes are downloaded transiently; their SHA-256, source URL and conversion code version are recorded in the publication commit, not as adjacent corpus files.

The separate [regional collector](../../../../../scripts/capture_cbr_offices_reg.py) and [monthly discovery workflow](../../../../../.github/workflows/capture-cbr-offices-reg.yml) check the official index daily at 02:17 UTC (05:17 UTC+03), retrieving missing releases newer than the latest archived monthly date. A missing new official release creates no file; a new release creates one CSV, never a synthetic daily snapshot. The workflow's manual `backfill` mode retrieves missing historical reference dates, `verify` checks existing CSVs, and `dry_run` suppresses publication. An existing file is never silently overwritten.

**Do not combine, add or compare territorial rows as if they were disjoint.** The monthly tables can contain country, district, region and nested territorial totals (for example autonomous okrugs within regions). Absence of an indicator column is not zero. Any harmonization of categories, dates, boundaries or territorial nesting is a separate, documented analytical bridge and not part of this evidence layer.

Treat identifier and textual source columns as text when importing CSV into spreadsheet software. Neither CSV representation is an official source CSV or a full preserved source publication. Source strings beginning with spreadsheet formula characters are preserved and are not made safe for direct spreadsheet opening.
