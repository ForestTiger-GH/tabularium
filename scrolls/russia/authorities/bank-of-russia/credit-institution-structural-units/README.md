# Credit institution structural units

Dated, source-faithful **wide CSV** extractions of the Bank of Russia's [regional table of credit-institution structural units](https://www.cbr.ru/banking_sector/credit/cstat/). Each `YYYY/OFFICES_YYYY-MM-DD.csv` is named for the retrieval calendar date in fixed UTC+03:00, **not** the source's statistical reference date. Every observed source data row appears once, with its published indicators in separate columns.

Automated captures use the actual retrieval date in fixed UTC+03:00. Retrospectively uploaded historical snapshots also appear in the year directories; their filenames alone do not independently establish when the source was retrieved. Some older CSV representations contain an empty `section_label` for certain regions. Do not infer or silently replace it with the later `-` label: unknown in that representation is not the same as an explicit source label.

The first two columns, `source_row` and `section_label`, are extraction traceability fields: respectively the one-based physical HTML table row index (including headers and section rows), and the last preceding territorial section label (including `-`). **All subsequent columns retain the source's published header names and column order**, including its original region, credit-institution name, registration number and indicator labels. An observed header with four indicators is `source_row,section_label,Регион,Наименование КО,Рег. № КО,Головные офисы,Филиалы,Допофисы,Всего подразделений`. Published indicator headings may evolve between captures; the schema does not invent or normalize indicator names.

Published cell text is retained after HTML entity decoding and whitespace folding. No values are calculated, harmonized, inferred, or transformed into numeric types. An empty value is **not** zero: blank, `0` and `—` remain distinct. The source's registration number is text, even if it resembles a number. Territorial section rows are represented by `section_label` on subsequent rows rather than duplicated as data rows. Unexpected full-width text rows and missing territorial sections stop the capture rather than being silently omitted.

This is a CSV representation of one HTML **table**, not an official CSV, a full preserved HTML publication, or an analytical series. HTML layout and explanatory notes outside the table are not archived. The capture checks the source's known note about federal-district order following the All-Russian Classification of Economic Regions (OKER), but changes to other off-table context or underlying methodology may not be detected. Source revisions between snapshots may be missed. Verify material interpretations against the primary publisher.

Import all identifier and text fields as **text** in spreadsheets; source strings beginning with spreadsheet formula characters are not altered or made safe for direct spreadsheet opening.

The [collector](../../../../../scripts/capture_cbr_offices.py) and [daily workflow](../../../../../.github/workflows/capture-cbr-offices.yml) implement capture at 01:17 UTC (04:17 fixed UTC+03:00), with manual dispatch also available. Capture and publication use separate jobs and SHA-256 artifact verification. The publisher accepts only a new date path or an identical rerun, never a silent overwrite. GitHub may delay or skip scheduled runs, and missing dates are never backfilled from later observations. An independent [read-only daily checker](../../../../../.github/workflows/check-cbr-offices.yml) verifies that today's dated CSV is present and valid at 09:17 UTC; a failed check creates no corpus files and must not be repaired by falsifying an observation date. [CI validation](../../../../../.github/workflows/validate-cbr-offices.yml) separately checks workflow syntax and extraction tests on relevant pushes and pull requests; it does not replace branch protection. The `contents:write` permission is not technically restricted to one file path; reviewed code and branch controls remain important.
